# new:view — Professional Regression Demo

## Purpose

`DemoUse.txt` is the repeatable regression test for the E4ProTech StarterKit generator.

Use it whenever `new:view`, `remove:view`, Reverb, Flutter generation, image handling, localization, API behavior, or generated UI changes.

The purpose is simple:

> Change the generator → run the same demo → verify the entire generated ecosystem.

---

# 1. Git Baseline

Before major generator changes:

```powershell
git add .
git commit -m "chore: starterkit baseline"
git tag v1.0.0-starterkit
```

For experimental generator work:

```powershell
git switch -c demo/new-view-test
```

Recommended workflow:

```text
StarterKit baseline
      ↓
Run new:view demo
      ↓
Inspect generated application
      ↓
Fix generator
      ↓
Run demo again
      ↓
Commit only when the regression test passes
```

# 18. Firebase Test

For the baseline demo:

```text
Firebase = OFF
```

This means:

```text
Reverb = ON
Firebase = OFF
```

Optional Firebase generation:

```powershell
php artisan new:view TestModule --api --firebase
```

The expected architecture remains:

```text
Database change
     │
     ├──► Reverb → realtime UI
     │
     └──► Firebase → push notification
```

Firebase must not replace Reverb as the realtime transport.

When enabled, successful operations should produce meaningful push messages such as:

```text
TestModule u shtua
TestModule u përditësua
TestModule u fshi
```

Failed API/database operations must not produce a success push.

# 19. API ACK Test

Every mobile mutation should be tested in two states.

## Success

```text
Request
  ↓
HTTP 2xx
  ↓
DB operation succeeds
  ↓
Flutter success state
```

## Failure

```text
Request
  ↓
HTTP error / validation / timeout
  ↓
Flutter failure state
```

Verify that the app can distinguish:

```text
successful response
failed response
no response / network problem
```
